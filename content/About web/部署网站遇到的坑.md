## 1. 核心踩坑与破局复盘 (Troubleshooting)

### 🛑 坑 1：Windows CMD 环境下的参数解析冲突
* **现象**：在本地修改完配置后，运行官方同步命令 `npx quartz sync --commit "message" --push` 时，终端疯狂报错 `Unknown argument: ...`。
* **原因**：Windows 的 CMD 终端对 Quartz 内部解析器的空格和双引号支持不够彻底。哪怕加了双引号，Quartz 依然会自作聪明地把 Commit 信息按空格切分成一堆独立参数，导致解析崩溃。
* **破局**：**降维打击，改用 Git 原生三板斧。** 抛弃 Quartz 的 `sync` 外壳，直接在根目录运行标准的原生命令，安全且绝对不会误判：
  ```bash
  git add .
  git commit -m "Sync content and configurations"
  git push origin v4
```

### 🛑 坑 2：大水冲了龙王庙——Vercel 仓库绑定错误

- **现象**：Vercel 部署速度极快（只需几秒），但点击域名进去后，整个网页空空如也，只有一行毫无样式包裹的原始 `index` 文本，或者直接触发浏览器下载二进制文件。
    
- **原因**：在 Vercel 导入项目时，误将你的 **Obsidian 纯笔记私有库 (`my-vault`)** 直接当作前端项目导入了，而没有绑定 **Quartz 4 框架库 (`NX-diGarden`)**。导致 Vercel 拿着纯文本去编译，根本没有加载任何前端渲染引擎和 $\LaTeX$ 插件。
    
- **破局**：在 Vercel Dashboard 中点击 `Add New Project`，**精准选择公开的框架库 `NX-diGarden` 进行 Import**。
    

### 🛑 坑 3：Git 子模块 (Submodule) 变质引起的云端死锁

- **现象**：Vercel 绑定正确后，编译日志高亮报错 `Warning: Failed to fetch one or more git submodules`，且构建在 200 毫秒内瞬间结束。
    
- **原因**：本地的 `content` 文件夹在频繁的变更中，其底层指针在 Git 缓存里意外降级变成了一个带有特殊哈希值的“子模块快捷方式（断头软链接）”。由于云端 Vercel 没有克隆私有库的最高权限或 Token 路径错位，它在拉取时直接被卡死在门外，导致生成的网站没有一个具体的页面肉身。
    
- **破局**：**彻底洗净 Git 底层记忆。** 在本地终端运行以下组合拳，强制拔除变质的子模块索引，让 `content` 回归清白的身分：
    
    Bash
    
    ```
    git rm -f content
    git rm --cached content -f
    ```
    

### 🛑 坑 4：Linux 构建脚本的“隐形权限卡脖子”

- **现象**：配置了云端拉取脚本 `vercel-install.sh` 并在 Vercel 中开启了 `INSTALL COMMAND` 覆盖，但云端依旧无视脚本，死活不肯去私有库拉取内容。
    
- **原因**：我们在 Windows 环境下创建并推上去的 `vercel-install.sh`，在 Linux/云端打包环境里**默认是没有可执行权限的**。Vercel 走到这一步因为 `Permission denied` 被迫静默跳过，导致自动化拉取完全沦为摆设。
    
- **破局**：利用 Git 的底层索引权限管理工具，**强行在代码层面给脚本赋予可执行绿卡（Linux 755 权限）**：
    
    Bash
    
    ```
    git update-index --chmod=+x vercel-install.sh
    git commit -m "Fix: Grant executable permission to deployment script"
    git push origin v4 --force
    ```
    

### 🛑 坑 5：Quartz 4 内部 `baseUrl` 引起的域名路由错位（终极 404 顽疾）

- **现象**：Vercel 编译终于大获成功（Ready），点开项目也能看到所有拉取过来的几百 KB 静态 HTML 资源（如测地线、相对论笔记），但点开主页后的任何子文章链接全是 404。
    
- **原因**：Quartz 4 框架内部的 **`quartz.config.ts`** 里有一个核心参数叫 `baseUrl`。如果这个参数里的域名跟你在 Vercel 上实际访问的域名（比如带随机字符的测试分支域名）没有做到绝对对齐，Quartz 内部的路由映射表就会产生严重的跨域错位，导致服务器直接找不到页面。
    
- **破局**：
    
    1. 打开本地的 `quartz.config.ts`，将 `baseUrl` 精准修改为你正式的 Production 主域名：
        
        TypeScript
        
        ```
        baseUrl: "nx-di-garden.vercel.app", // 前面不带 https://，后面不带斜杠
        ```
        
    2. 强推上云后，**务必使用浏览器的无痕模式 (Privacy Window) 或者通过 `Ctrl + F5` 强刷**来直接访问你的正式主域名。彻底绕过本地浏览器对旧 404 页面产生的顽固本地强缓存。
        

## 2. 日常推送与同步流程 (Daily Push Workflow)

经历了一整晚的极限排毒，现在本地和云端的“输油管道”已经彻底全线贯通。以后更新数字花园，你完全可以回归到最习惯的、两边分立的自动化流程，再也不需要手动复制粘贴：

### 🔄 完美的日常双轨发布流：

1. **本地正常写作 (D盘)**：
    
    你在 Obsidian 里面快乐地推导微分几何、广义相对论。写完后，利用 Obsidian Git 插件或者命令，直接把改动推送到你的 **GitHub 私有库 (`my-vault`)**。
    
2. **本地一键同步指针 (F盘 CMD)**：
    
    因为公开库里现在已经没有庞大的真实笔记文件了，它只需要记录一个“子模块指针”。在 D 盘推完笔记后，顺手打开 F 盘的 CMD 终端，敲下这两行（或者写成一个 `.bat` 批处理双击运行）：
    
    Bash
    
    ```
    # 让本地的子模块去同步你刚刚推上 GitHub 私有库的最新笔记
    git submodule update --remote --merge
    
    # 把最新的指针状态推上你 GitHub 的公开框架库 (NX-diGarden)
    git add .
    git commit -m "Sync: Update notes pointer to latest research log"
    git push origin v4
    ```
    
3. **云端全自动收网 (Vercel)**：
    
    当你把 F 盘的最新指针推上去的那一刻，Vercel 会立刻被唤醒。它会老老实实地运行 `npm run vercel-install`，带着你的密码本闪现到你的私有库里把最新笔记扯过来，全自动调用 Quartz 4 引擎在后台花 30 秒自动完成渲染发布！
